# Login fix - 2026-10-07

Fixed the Supabase login flow.

## Root cause
The `onAuthStateChange` callback awaited a second Supabase query (`loadProfile`). Supabase auth callbacks should stay synchronous; waiting on another Supabase request from inside that callback can block the login event and make `signInWithPassword` appear stuck.

## Changes
- Auth-state callback is now synchronous.
- Profile loading is deferred and cannot block successful login.
- Successful authentication no longer depends on the `profiles` table query succeeding.
- Added network/auth exception handling.
- Improved session initialization and cleanup.
- Resend-confirmation button only appears for actual unconfirmed-email errors.
- Password reset redirect uses the current app origin.

## Render environment variables
Set these before building/deploying:
- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY` (preferred) OR `VITE_SUPABASE_ANON_KEY`

After changing Vite environment variables on Render, redeploy/rebuild the service because `VITE_*` values are bundled at build time.
